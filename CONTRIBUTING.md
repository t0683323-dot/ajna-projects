# Contributing to Ajna Projects

Thanks for your interest in improving this repository. We welcome bug reports, documentation updates, and code contributions.

## Before You Start

- Check existing issues and pull requests to avoid duplicate work.
- For larger changes, open an issue first to discuss scope and approach.
- Keep changes focused and atomic.

## Issue Standards

When opening an issue, please include:

1. **Summary**: A clear, concise title.
2. **Context**: Why this matters and the expected behavior.
3. **Reproduction** (for bugs): Steps, environment, and observed behavior.
4. **Acceptance Criteria**: How we know the issue is resolved.
5. **Artifacts**: Logs, stack traces, screenshots, or minimal repro if available.

### Issue Labels (Recommended)

- `bug`: Something is broken.
- `feature`: New capability or enhancement.
- `docs`: Documentation-only work.
- `chore`: Maintenance/refactoring.
- `good first issue`: Suitable for new contributors.

## Pull Request Standards

### PR Checklist

Before opening a pull request:

- [ ] Link the related issue (e.g., `Fixes #123`).
- [ ] Keep the PR limited to a single logical change.
- [ ] Include or update tests where appropriate.
- [ ] Update docs/config/examples if behavior changes.
- [ ] Ensure local checks pass.

### PR Description Template

Please include:

- **What changed**
- **Why it changed**
- **How it was tested**
- **Any migration or rollout notes**

### Review Expectations

- Maintainers may request updates before merge.
- Be responsive and keep discussion constructive.
- Squash/rebase commits if requested to keep history clean.

## Coding & Commit Guidelines

- Follow existing conventions and project structure.
- Prefer small, readable functions and clear naming.
- Write commit messages in the imperative mood (e.g., `Add input validation for X`).

## Community Conduct

By participating, you agree to follow the [Code of Conduct](./CODE_OF_CONDUCT.md).
